# Task Manager

Приложение для управления списками задач: списки со счётчиками и прогрессом, таблица задач с сортировкой по дедлайнам, карточка задачи, тема light / dark / system.

**Демо:** _(ссылка появится после деплоя)_

**Демо-доступ:** `admin@example.com` / `Admin123!`

## Запуск

Нужен Node.js 24 (версия зафиксирована в `.nvmrc`).

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:3000. Переменные окружения не нужны.

## Возможности

- **Вход** — форма с валидацией, состоянием загрузки и ошибкой от сервера. Маршруты `/lists` и `/tasks` закрыты для неавторизованных.
- **Списки задач (`/lists`)** — карточка показывает название, счётчики new / in progress / done / overdue, прогресс и цветную полосу: красная, если есть просроченные задачи, жёлтая, если дедлайн в ближайшие 48 часов. Цвет всегда продублирован текстом. Списки можно создавать, переименовывать, удалять и искать.
- **Задачи списка (`/lists/[id]`)** — таблица с названием, статусом, приоритетом и дедлайном. Задачу можно добавить, изменить, удалить, сменить ей статус прямо в таблице и отфильтровать список по статусу.
- **Карточка задачи (`/tasks/[id]`)** — название, описание, статус, приоритет и дедлайн, сохранение через API.
- **Тема** — светлая, тёмная и системная. Выбор хранится в cookie, поэтому сервер сразу отдаёт страницу в нужной теме.

### Сортировка задач

1. Незавершённые просроченные — выше всех.
2. Чем ближе дедлайн, тем выше.
3. При равных дедлайнах решает приоритет: high, medium, low.
4. Выполненные — внизу.

Первое правило выполняется вторым: у просроченной незавершённой задачи дедлайн всегда раньше, чем у непросроченной.

## Слой данных

Источник правды — сервер. В компонентах нет ни состояния с данными, ни импорта JSON.

```
Чтение     страница (серверный компонент) → репозиторий → хранилище
Запись     клиент → src/api-client → app/api/**/route.ts → репозиторий → хранилище
```

- **Чтение** происходит в серверных компонентах: страница напрямую вызывает репозиторий, без HTTP-запроса к собственному API.
- **Запись** идёт через route handlers в `src/app/api`. Каждый обработчик проверяет cookie входа, разбирает тело запроса zod-схемой и возвращает единый формат `ApiResult`: `{ ok: true, data }` либо `{ ok: false, error, fieldErrors }`. Коды ответов: 200 и 201, 400 при ошибке валидации, 401 без входа, 404 если объект не найден.
- **После мутации** клиент вызывает `router.refresh()`: Next перезапрашивает серверные компоненты текущей страницы, и таблица приходит уже с новой сортировкой и счётчиками.
- **Хранилище** — массивы в памяти сервера (`src/server/data/store.ts`). Репозитории — единственное место, которое о нём знает, поэтому замена на базу данных затронет только их.
- **Валидация написана один раз.** zod-схемы лежат в `src/domain`, форма подключает их через адаптер `zodRule`, обработчик API — через `safeParse`. Пользователь и сервер видят одинаковые сообщения об ошибках.

Ограничение демо: данные живут в памяти процесса, поэтому при перезапуске сервера возвращаются стартовые.

## Тесты

```bash
npm test              # юнит-тесты домена (Vitest)
npm run test:storybook   # тесты историй Storybook в Chromium
```

Перед первым запуском тестов Storybook нужно скачать браузер:

```bash
npx playwright install chromium
```

- **9 юнит-тестов** на чистую доменную логику: 5 на счётчики и индикатор карточки списка, 4 на сортировку задач.
- **6 историй с `play`**: валидация формы входа, отправка формы, ошибка сервера, обработка пробелов, создание списка, смена статуса задачи.

Оба набора запускаются одной конфигурацией `vitest.config.mts`, разделены на проекты `unit` и `storybook`.

## Структура

```
src/app          страницы (тонкие серверные компоненты) и app/api/**/route.ts
src/proxy.ts     защита маршрутов
src/domain       чистый TypeScript: типы, zod-схемы, дедлайны, сортировка, статистика, тесты
src/server       код только для сервера: cookie входа, хранилище, репозитории, ответы API
src/api-client   запросы к своим API, возвращают ApiResult
src/features     интерфейс по фичам: презентационные компоненты, контейнеры и истории
src/shared       тема, общие компоненты и функции, общие типы
```

Правила зависимостей: `domain` ни от чего не зависит, `server` использует `domain`, `features` не импортирует `server`, страницы могут использовать всё.

## Решения, о которых стоит знать

- **Авторизация упрощена.** Учётные данные из условия задания лежат в обработчике `POST /api/auth/login`, после проверки ставится httpOnly-cookie-флаг. Ни базы пользователей, ни подписанных токенов здесь нет, это демо.
- **Время показывается в поясе `Europe/Minsk`** (`src/shared/lib/date.ts`). Таблица сначала рисуется на сервере, а он не знает пояс пользователя: если форматировать по местному времени браузера, сервер и клиент покажут разное и React сообщит об ошибке гидрации. В реальном продукте пояс брался бы из настроек пользователя.
- **Тема приходит с сервера.** Ant Design генерирует цвета на сервере, поэтому выбор темы хранится в cookie, а тема операционной системы определяется заголовком `Sec-CH-Prefers-Color-Scheme`. Если браузер его не поддерживает, скрипт в `<head>` один раз перезагружает страницу до отрисовки — так тёмная тема не мигает светлой.
